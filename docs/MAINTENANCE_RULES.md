# NerfLens / GTNH 开发、汉化、升级与发布注意表

整理日期：2026-11-26。适用对象：NerfLens 维护者及后续修改本项目的助手。

这份表将已发生的问题和当前实现约束整理为执行标准。每条“验收点”是以后修改时需要核对的项目，不能直接当作本次已全部完成游戏验收的证明。当前用户请求、授权范围和偏好优先；历史截图中的操作记录只提供背景。

P0：数据正确性、可读性、误标、版本声明或存档风险；P1：兼容、维护与发布质量；P2：记录与复现。

## 1. Tooltip 可读性与布局

| 编号／级别 | 注意项 | 执行规则 | 验收点 |
| --- | --- | --- | --- |
| T01／P0 | 长提示极难阅读 | 默认显示关键摘要、原版与现版；Shift 展开细节。摘要保留数量、单位、变化方向和适用路线。不要把整篇机器说明塞进默认悬停。 | 默认状态能直接读出“什么变了、变多少”；Shift 能找到完整限制。 |
| T02／P0 | 正文颜色 | 正文使用清晰、足够对比的颜色，标题、标签、数值和警告少量区分。语义不能只靠颜色表达。金框和标题强调色不应把整段正文染成同一种颜色。 | 在真实深色 tooltip 背景上读得清；截图中的正文、数值和警告均可辨认。 |
| T03／P0 | 中文换行与缩进 | 根据实际 FontRenderer 字宽换行，预留前缀宽度，先折行再加缩进；处理真实换行。保持数值与单位、短物品名完整。 | 无逐字裂行、空白行堆积、前缀占满行宽或单位落单。 |
| T04／P0 | 画面边界 | 同时考虑窗口尺寸、GUI Scale、鼠标位置、屏幕边缘、NEI 搜索栏和底部对照区。内容过长时采用摘要或分组；不能靠缩小文字掩盖溢出。 | GUI Scale 1／2／3／4／Auto、窗口和全屏的适用样例不越界、不盖按钮。未测试的组合写为待验收。 |
| T05／P0 | 原版与现版 | “原版”默认指原整合包；ExtraNerf 上一版本的增量单独标注。完整数量优先，单位统一。只有确有帮助时补百分比。 | 盐酸示例明确 `3,000 → 2,000 mB，减少 1,000 mB（33.3%）`，不会混淆上一版和原整合包。 |
| T06／P0 | Shift 丢失摘要关键点 | 展开详情时也保留摘要中的关键规则；新增规则同时更新摘要与详情。 | 凯芙拉亲本、7.5% 特产概率、64 蜂窝投入在适用展开说明中均能找到。 |
| T07／P1 | 公式与标签 | 保留运算顺序、括号、百分号与变量；颜色标签只使用当前提供者支持的语法。GT 动态标签与普通 NerfLens 文本分开处理。 | 不显示裸露的 `{color_*}`、未解析变量或错误 `%`；公式与原生规则一致。 |
| T08／P1 | 中英文一致 | 同一条记录的中英文数量、方向、条件和产物对应；中文说明尽量使用已核对的译名，必要时首次附英文。 | 切换语言不丢信息，也不把上一语言的命中缓存带过去。 |
| T09／P0 | 验收证据 | “JSON 有文字”“构建通过”“测试夹具命中”“真实配方页可见”“真实加工结果”分别记录。文件中存在说明不能证明游戏显示成功。 | 结论明确验证环境与实际完成的层级；截图故障必须在相同悬停对象与配方页复现。 |

## 2. Tooltip 数据写入与配方匹配

| 编号／级别 | 注意项 | 执行规则 | 验收点 |
| --- | --- | --- | --- |
| D01／P0 | 显示辅助边界 | NerfLens 读取物品、配方、翻译和认证状态。显示改动写入自身资源／配置，不改真实配方、机器加工、考试或世界认证记录。 | 无修改 RecipeMap、ItemStack、世界 MapStorage 或认证持久状态的显示回调。 |
| D02／P0 | 内置档案与用户配置 | 内置记录放在对应版本资源中。用户 `user_nerfs.json` 按 ID 覆盖；带 `extraNerfVersion` 的文件只应用到匹配版本。维护内置档案时保留用户覆盖文件。 | 用户记录不会串到旧版／未知版，已有自定义配置不会被默认文件覆盖。 |
| D03／P0 | 真实标识 | 以实际加载的物品 ID、metadata、矿辞、流体名与阶段为准；必要时检查原生 JAR／客户端注册表。文档与代码不一致时查运行代码。 | 太阳能级硅使用 `dustSiliconSolarGrade`，不使用不存在的 `dustSiliconSG`；蜂窝核对 `gregtech:gt.comb:161`。 |
| D04／P0 | 路线范围 | 使用机器配方表、输入、输出、数量、电路、流体阶段、NBT 和必要排除条件共同约束。只改特定路线时保留局部显示。 | 相同材料的未改动路线没有误标；正例、邻近 metadata、错数量和不同电路均有对照。 |
| D05／P0 | 选择器语义 | 当前 `StackSpec` 的 `gt`／`mod`／`item`／`unloc` 等是分支选择器，不自动构成 AND；`any` 表示 OR。新增复合约束必须明确实现语义。 | 不因同时填写 `mod` 与 `unloc` 就误标整个模组；核对实际执行的分支。 |
| D06／P0 | 精确匹配优先 | 当前 `matchStacks` 会取代同一条 Entry 的名字／unloc 命中。一个记录同时覆盖控制器和物品时，精确选择器要覆盖每种对象，或拆开记录。 | QFT 控制器和凯芙拉蜂窝分别命中；其他蜂窝不会继承说明。 |
| D07／P0 | 输入黄框与产物金框 | 黄框只标本配方已改变的投入。局部金框标受影响目标产物或明确改变的副产物；全局金框只用于已验证的材料生产变化。 | 被改变用途的原料、删除路线、产量变化和公共副产物不会因此获得全局金框。 |
| D08／P0 | 多产物与公共材料 | `outputs` 用于配方身份，`products` 明确需要生产说明的目标。盐酸、水、盐粉等公共副产物按是否真正变化判断。 | QFT 的目标塑料可标，未改变的异种烯／重 Radox 不继承塑料金框。 |
| D09／P0 | 真实数量 | 读取 NEI 原生数量，包括 `realStackSize`、流体 mB 与图标隐藏数量模式。不要根据图标显示的 `stackSize=1` 推算配方成本。 | 普通图标与归一化图标给出相同原版／现版对照；数量变化会使缓存失效。 |
| D10／P0 | NBT、蜂与容器 | 比较 NBT 变体、蜂的显性物种与品级，以及容器／空容器分支。显性蜂种使用原生 Forestry API 的结果。 | 隐性凯芙拉、错误蜂种、空容器和同 ID 不同 NBT 均不误标。 |
| D11／P0 | 复用页面缓存 | 数据库、语言、资源包、输入、输出、数量、候选物品或 NBT 改变时，重新匹配。不能仅以 handler 和页码作为缓存身份。 | 在同一 NEI 页面替换物品／数量后，旧框与旧说明消失；正确条件恢复后再次命中。 |
| D12／P0 | 认证状态读取 | 只读取已加载状态；服务器线程读取，世界／服务器切换后清空快照。远程服务器未提供状态时显示未知。证书物品看自身，机器看完整前置链。 | 撤销蒸汽证书不会错误显示仍拥有的 LV 证书丢失；无创建、保存或 dirty 世界数据调用。 |

## 3. 多版本与候选发布

| 编号／级别 | 注意项 | 执行规则 | 验收点 |
| --- | --- | --- | --- |
| V01／P0 | 三组版本 | 分别记录 GTNH 整包、ExtraNerf 本体和 NerfLens 辅助模组版本。不同版本号承担不同职责。 | 本次目标明确为 GTNH 2.9.1、ExtraNerf 1.3.0、NerfLens 0.3.1。 |
| V02／P0 | 精确选择档案 | 从 Forge 实际加载元数据选择已验证档案；支持明确的 `v` 前缀与 `+build`。未知版本、未验证 rc／beta 和未安装状态保留未知／用户数据策略。 | 不凭文件名或宽泛 `1.2.x` 自动继承规则。已知／未知／缺失版本均有检查。 |
| V03／P0 | 旧档案冻结 | 新版本新增独立档案，保持旧版本记录。必要时用原发布 JAR 的资源字节作为基准，并固定换行策略。 | 1.2.0 继续保留整份奇异粉，1.2.1 使用小撮；旧资源 SHA-256 与基准一致。 |
| V04／P0 | rc 的含义 | `rc` 是候选发布标识。构建版本、Mods 版本、JAR 文件名、源码、说明、Tag 和 Release 类型一致；正式版变更不能只靠改文件名完成。 | 游戏实际加载的版本与发布声明一致；候选与正式声明有对应的验证记录。 |
| V05／P1 | 版本矩阵 | 升级整包也升级实际 API 验证。旧 GTNH 的成功记录不能直接代替新 NEI／Chromatic／GregTech 环境的结果。 | 2.9.1 使用 NEI 2.8.175 与 Chromatic 1.0.38 重跑相关检查，并记录 JAR 标识。 |
| V06／P1 | 构建与对应源码 | 显式声明版本，源码包可以在没有 `.git` 的情况下构建。验证脚本可选择匹配依赖；不能硬编码成只支持某个旧安装目录。 | JAR、源码资源、构建版本一致；源包不混入本机缓存、日志与游戏数据。 |

## 4. 汉化与文本来源

| 编号／级别 | 注意项 | 执行规则 | 验收点 |
| --- | --- | --- | --- |
| L01／P0 | 既有译文优先 | 保留游戏原有的模组、TX Loader、资源包与动态注入优先级；NerfLens 仅在最终缺译时补缺。外部刻意保留的英文也视为已提供内容。 | 不覆盖已有中文或刻意保留的英文；资源包重载后的结果可追溯。 |
| L02／P0 | 原文核对 | 缺译补丁必须匹配当前来源的英文参考。英文含义变更时增加独立译文分支，旧原文仍选旧译文。 | 铁浴测量仓的“侧平台”和“烟囱”分别对应 1.2.0 与 1.2.1 原文。未知新含义不会套用旧译文。 |
| L03／P0 | 动态材料名称 | 没有语言文件参考的动态名称，需要已验证的提供者版本、正确原生英文与缺译状态共同满足。 | 1.2.0／1.2.1 可使用对应材料补缺；其他版本与已翻译文本保留原结果。 |
| L04／P1 | 占位符与转义 | 保留 `%s`、`%1$s`、`%%`、实际换行及各类原生文本变量；按照游戏语言加载方式处理数值格式与 CRLF／LF。 | 实际格式化能运行，百分号与参数不丢失；不能用带回车的测试字符串伪装成外部译文。 |
| L05／P1 | 中文名称来源 | 优先使用当前整包／原生模组已核对的中文名称；新术语标明补缺译文来源。数量、矿辞与规则由运行代码决定。 | 不用机器翻译猜物品注册名；正文不遗留整段未核对的英文规则。 |
| L06／P0 | 整包汉化合并 | 新官方汉化作为基底，保留真实本地差异。区分换行、注释、自动生成内容与用户修改；任务书语言按三方内容合并。 | 新任务文字与键存在；不把旧版官方文件整份覆盖回新版，也不丢本地确有的改动。 |

## 5. GitHub 发布文字与附件

| 编号／级别 | 注意项 | 执行规则 | 验收点 |
| --- | --- | --- | --- |
| G01／P0 | 发布动作范围 | 文案准备、安装、提交、推送和正式发布分别遵循当前授权。整理“发布文字规则”本身不代表要求对外发布。已授权的步骤无需重复确认。 | 对外动作与用户要求相符；结果记录已安装、已提交、已推送、已发布的实际状态。 |
| G02／P1 | 标题与首段 | 标题写版本和具体适配／修复。首段说明玩家会看到的变化；正文围绕最终实现，不写聊天经过、工具调用流水或已放弃方案。 | 玩家能直接判断兼容版本、是否需要升级和实际改变。 |
| G03／P0 | 准确声明验证 | 分开列出构建、测试夹具、原生 API／字节码、游戏画面和实际加工验证。给数量和环境，写清必要边界。 | 不把“已写进文件”写成“游戏已显示”；不把夹具通过写成所有机器已在真实存档验收。 |
| G04／P1 | 文案结构 | 按“支持版本 → 玩家变化 → 安装方式 → 验证”组织。数量使用完整单位；复杂机制给一个明确前后例子，避免冗长宣传和实现术语。 | 玩家安装段能独立执行，默认／Shift 的行为与实际一致。 |
| G05／P0 | Release 元信息 | Tag、标题、正文、附件名称、内部版本与 stable／prerelease 状态核对一致。源码与运行 JAR 对应。 | Mods 页显示的版本与下载附件一致；发布页面不挂已删除或尚不存在的下载链接。 |
| G06／P1 | 可用附件 | 提供安装 JAR、对应源码、更新说明、验证记录与 SHA-256。说明安装哪个文件，以及升级时每种模组只保留一个版本。 | 下载附件与本地 JAR 的 SHA-256 一致；完整离线包内容能解压、能校验。 |
| G07／P0 | 公开内容清理 | 公开源包排除本机绝对路径、用户账号、密钥、存档、备份、日志和构建缓存；保留许可证、上游来源与必要验证资源。 | 源码扫描通过；个人安装／备份记录作为本地记录，不混入公开发布附件。 |
| G08／P1 | 文案随最终范围更新 | 如果实现、兼容环境或附件变了，重新核对整篇发布说明。状态变化用新记录保存，不改写旧验收历史。 | 文案没有沿用旧 rc 或旧整包的描述；历史留存包仍可按原校验值核对。 |

## 6. GTNH 直接替换升级与回退

| 编号／级别 | 注意项 | 执行规则 | 验收点 |
| --- | --- | --- | --- |
| U01／P0 | 客户端关闭 | 替换前检查实际 GTNH Java 进程和正常退出记录。用户仍在游戏时先保留包；没有保存退出时不强制关闭。 | 替换时客户端关闭，避免文件锁和未保存进度。 |
| U02／P0 | 官方整包来源 | 从官方页面获取指定版本与 Java 代际的整包，检查长度、ZIP 完整性并记录本地 SHA-256。没有上游 SHA 时，不把本地 hash 说成已与上游 SHA 对照。 | 本次来源为官方 2.9.1 Java 17–26 包；实际保留 Java 21。 |
| U03／P0 | 完整替换范围 | 原实例升级需一起替换官方 `mods`、`config`、`serverutilities`；Java 17+ 同时更新 `libraries`、`patches` 和 `mmc-pack.json`。显示版本与实际内容一致。 | LWJGL3ify 模组、补丁、早期 classpath 与启动参数对应；不是只改实例名称。 |
| U04／P0 | 附加模组 | 先对照旧官方清单，识别真正附加／修改的文件，再并入新版。保留禁用状态，按实际 Mod ID 防止重复版本。 | 本次 9 个附加文件保留，FMusic 继续禁用；NerfLens 和 ExtraNerf 各只有一个有效 JAR。 |
| U05／P0 | 配置基底 | 以新版官方配置为基底，带回真实个人设置、附加模组配置和必要本地内容。核心版本字段与新官方一致；既有世界的 biome／维度 ID 先核对。 | 新版官方修复与个人设置同时保留；RWG2 既有 biome IDs 一致；无合并冲突标记。 |
| U06／P0 | 用户数据 | 保留存档、NEI 数据、地图、矿脉／节点记录、资源包、截图、蓝图、键位、服务器列表与权限。替换前做存档备份和清单。 | 备份 ZIP 能解压、文件数和校验一致；原存档与选项不因升级脚本而改变。 |
| U07／P0 | 原子替换与回退 | 先完成暂存和检查，再把旧目录移到明确的备份位置，安装新版；失败时恢复已移动的目录和实例元数据。Windows 路径先解析并确认在指定目录内。 | 旧 mods／config／补丁和实例配置可恢复，实际目标路径未越界。 |
| U08／P0 | 升级后的验证层级 | 核对所有官方文件和附加文件、版本显示、关键依赖与 Mod 重复；再分别记录启动到主菜单、加载存档和代表机器验收。 | 没有进行的实际启动／存档验收明确写为待完成，不自动确认缺失方块。 |

## 7. 问题复现与日常维护

| 编号／级别 | 注意项 | 执行规则 | 验收点 |
| --- | --- | --- | --- |
| Q01／P0 | 同类问题一起审计 | 找到一个错误标识、NBT 误标或公共材料误标后，检查相同字段、提供者与路线类型，不只改截图中的一个对象。 | 有相邻对象／路线的反例；有受影响记录清单。 |
| Q02／P0 | 临时修复与持久修复 | 当前客户端重载只能证明当前会话的显示变化。持久修复必须进入对应 JAR，并在退出替换后核对。 | 磁盘上的实际 JAR 与验证包相同；不把临时热修复当作重启后已生效。 |
| Q03／P1 | 有意义的检查 | 沿用版本、显示边界、材料范围、语言优先级和 Mixin 检查；为新行为添加正反例。低风险纯文案变更核对实际内容即可，不堆实现镜像测试。 | 检查能发现真实误标／漏匹配，不只是数行数或证明自己写过文本。 |
| Q04／P1 | 构建环境故障 | 下载工具链失败与源码失败分别定位，优先复用已有合适 JDK／依赖缓存。保留完整日志，使用准确版本构建。 | 不用更改功能或关闭必要检查掩盖环境问题；构建结果可复现。 |
| Q05／P2 | 记录可追溯 | 保存上游提交、数据档案、源提交、JAR SHA-256、安装前后状态、备份路径与验证范围。数字统计从实际记录生成。 | 后续能判断当前加载的是什么、哪些做过验证、如何恢复。 |
